# 移行の手順書

Google スプレッドシートの選手名簿を、新システムへ移す手順です。
**設計の説明は [docs/import.md](import.md)、こちらは実際の作業手順です。**

## 事前に

- 移行できるのは `import.execute` を持つ人だけです（既定では管理者のみ）
- **元のスプレッドシートは消さないでください。** 移行が終わって、
  内容を確認して、しばらく使ってからにしてください
- 取り込みは取り消せます。恐れずに一度試してください

## 手順1: 元データを整える

スプレッドシート側で、次だけ確認してください。**完璧にする必要はありません。**

- [ ] 1行目が見出しになっている（「氏名」「学年」など）
- [ ] 1人1行になっている（結合セルを使っていない）
- [ ] 途中に小計行や空行が挟まっていない

見出しの言葉は揃えなくて構いません。
「名前」でも「選手名」でも「Player」でも自動で対応づけます。

学年の「3」「3年」「3年生」が混ざっていても大丈夫です。
ポジションの「FW」「フォワード」「Forward」も揃えなくて構いません。

### 分けたほうがよい場合

1枚のシートに複数学年が「見出し行つき」で並んでいる場合は、
学年ごとに分けて、複数回に分けて取り込むほうが確実です。

## 手順2: コピーする

1. スプレッドシートで、見出し行を含めて範囲を選択する
2. `Ctrl + C`（Mac は `Cmd + C`）

## 手順3: 貼り付ける

1. 新システムに管理者でログインする
2. 「データ移行」を開く
3. 「貼り付け欄」に `Ctrl + V` で貼り付ける
4. 「内容を確認する」を押す

CSV ファイルからでも構いません。「CSVファイルを選ぶ」を押してください。

## 手順4: 列の対応づけを確認する

自動で推測した結果が表示されます。**必ず目で確認してください。**

- 「推測」と付いている列は、自信が低い対応づけです
- 取り込みたくない列は「取り込まない」を選びます
- 直したら「この対応づけで再確認する」を押します

`氏名` は必須です。割り当てられていないと先へ進めません。

## 手順5: プレビューを確認する

```
総件数：235
正常：219
警告：13
エラー：3

新規：30
更新：202
スキップ：3
```

### エラーがある場合

行ごとに理由が出ます。

| よくあるエラー                             | 対処                                                   |
| ------------------------------------------ | ------------------------------------------------------ |
| 氏名が空です                               | 空行や小計行が混ざっている。元データから除く           |
| ポジションとして読み取れません（センター） | GK/DF/MF/FW/STAFF に直す。または「取り込まない」にする |
| 学年が範囲外です                           | 元データを確認する                                     |
| 同じ氏名の選手が2人います                  | 学年か入学年度の列を足して区別できるようにする         |

**エラー行があっても、他の行は取り込めます。**
後から直して、その行だけを取り込み直すこともできます。

### 警告がある場合

警告は「取り込むが、確認してほしい」ことです。

| よくある警告                | 意味                                               |
| --------------------------- | -------------------------------------------------- |
| 学年と入学年度が合いません  | どちらかが古い可能性がある。そのまま取り込まれる   |
| ○行目にも同じ氏名があります | 別人なら学年などで区別できるようにする             |
| 既に登録されています        | 既定では取り込まない。上書きしたいなら設定を変える |

## 手順6: 取り込む

「○件を取り込む」を押します。エラー行は自動的に除かれます。

## 手順7: 確認する

1. 「名簿」を開く
2. 人数を数える
3. 何人か抜き出して、学年・ポジション・背番号を元データと見比べる

**「未ログイン」と出るのは正常です。**
移行で登録した選手は、まだアカウントを作っていない状態です。

## 手順8: やり直したい場合

「データ移行」画面の下に「取り込み履歴」があります。
「取り消す」→「削除する」で、その回に追加した選手を消せます。

- 消えるのは**その回に新規作成した人**だけです
- **既にログインした人は消えません**（本人が使い始めている可能性があるため）
- 更新した内容は自動では戻りません

## 2回目以降の取り込み

同じデータをもう一度貼り付けても、二重登録は起きません。
既定（新規追加のみ）では、既に居る選手は「対象外」になります。

内容を更新したい場合は、「既存の選手と重なった時」を
**「既存を更新する」** に変えてください。

## 選手にアカウントを配る

移行が終わったら、選手がログインできるようにします。

現時点では Supabase の管理画面から作成します。

1. Supabase → Authentication → Users → Add user
2. 選手のメールアドレスとパスワードを設定する
3. SQL Editor で、作った利用者を既存のプロフィールに結び付ける

```sql
update public.profiles
set user_id = (select id from auth.users where email = 'senshu@example.com')
where email = 'senshu@example.com';
```

移行時にメールアドレスを入れていれば、この結び付けだけで
それまでの記録がその選手のものになります。

> 招待メールを送る機能は Phase 1 の残作業です（TASKS.md 参照）。

## 困ったとき

| 症状                     | 確認すること                                                  |
| ------------------------ | ------------------------------------------------------------- |
| 「データ移行」が見えない | `import.execute` を持っているか。既定では管理者のみ           |
| 貼り付けても表にならない | 1行目が見出しになっているか。スプレッドシートからコピーしたか |
| 文字化けする             | CSV なら UTF-8 で保存する。または貼り付けを使う               |
| 全部エラーになる         | 列の対応づけを確認する。氏名の列が正しく割り当たっているか    |
| 途中で切れる             | 10,000行の上限。分けて取り込む                                |
