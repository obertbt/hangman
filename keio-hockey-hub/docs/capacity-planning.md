# 容量の見積もり

## 1. なぜ制限するのか

動画は放っておくと際限なく増えます。
部の予算は限られていて、長く自分たちで運用し続ける必要があります。

だから「一番効く対策」を設計の中心に置いています。

> **長時間動画をアプリに保存しない。**
> YouTube に置き、必要な場面は「開始秒と終了秒」だけで表す。

## 2. 効き方

部員30名で1年間、次のように使ったとします。

| 使い方                                                        | 素直に保存した場合        | この設計の場合                |
| ------------------------------------------------------------- | ------------------------- | ----------------------------- |
| 練習全体動画 週2本 × 40週 = 80本（1本2GB）                    | 160GB                     | **0**（YouTube）              |
| 試合全体動画 20本（1本3GB）                                   | 60GB                      | **0**（YouTube）              |
| 上の動画から作った質問 1,000件                                | 1,000本の切り出しファイル | **0**（DBの1,000行 ≒ 数百KB） |
| 選手が撮った短編動画 30名 × 週1本 × 40週 = 1,200本（1本20MB） | 24GB                      | 24GB                          |
| プロフィール画像・日報添付                                    | 1GB                       | 1GB                           |
| **合計**                                                      | **約245GB**               | **約25GB**                    |

仮想クリップという考え方だけで、10分の1近くになります。

## 3. 既定の上限（58章）

| 設定                    | 既定値   | 環境変数                           |
| ----------------------- | -------- | ---------------------------------- |
| 動画の最大の長さ        | 60秒     | `MAX_VIDEO_DURATION_SECONDS`       |
| 動画の最大容量          | 50MB     | `MAX_VIDEO_SIZE_BYTES`             |
| 画像の最大容量          | 2MB      | `MAX_IMAGE_SIZE_BYTES`             |
| PDF の最大容量          | 10MB     | `MAX_PDF_SIZE_BYTES`               |
| 1日の動画投稿数         | 5件      | `MAX_DAILY_VIDEO_UPLOADS_PER_USER` |
| 署名付き URL の有効期限 | 15分     | `SIGNED_URL_EXPIRY_SECONDS`        |
| 一時アップロードの保持  | 24時間   | `TEMP_UPLOAD_RETENTION_HOURS`      |
| 論理削除ファイルの保持  | 30日     | `DELETED_FILE_RETENTION_DAYS`      |
| 取り込みファイルの上限  | 10MB     | `MAX_IMPORT_FILE_SIZE_BYTES`       |
| 取り込み行数の上限      | 10,000行 | `MAX_IMPORT_ROWS`                  |
| 保存容量の目安          | 25GB     | `STORAGE_LIMIT_BYTES`              |

将来は `app_settings` テーブルでチームごとに変えられるようにします。

`STORAGE_LIMIT_BYTES` は R2 の上限ではありません。
**「これを超えたら費用と運用を見直す」という自分たちの線引き**です。
0 にすると割合を出さず、使用量だけを表示します。

## 4. なぜ60秒なのか

技術的な限界ではありません。**使い方の設計**です。

5分の動画に「ここどうですか」と言われても、コーチはどこを見ればいいか分かりません。
15〜30秒に絞る作業そのものが、選手にとって
「何を聞きたいのか」を整理する時間になります。

断るときも、その意図が伝わる言葉にしています。

> 動画が長すぎます（上限 60秒、選択されたもの 90秒）。
> 見てもらいたい場面だけを切り出してください。

## 5. 保存期間（60章）

| 対象                                                         | 期間                |
| ------------------------------------------------------------ | ------------------- |
| シーズン / 日報 / スキル履歴 / フィードバック / トレーニング | 無期限              |
| 選手が投稿した動画                                           | 原則保持            |
| 監査ログ                                                     | 5年                 |
| 通知                                                         | 2年後にアーカイブ可 |
| 一時アップロード                                             | 24時間              |
| 論理削除したファイル                                         | 30日                |

記録は本人の成長の証拠なので、原則として消しません。

## 6. 監視

`storage_usage_snapshots` に記録します。
`/admin/storage` から `capture_storage_usage()` を呼んで数えます（`storage.manage` が要ります）。

| しきい値 | 状態 | すること                     | 実装     |
| -------- | ---- | ---------------------------- | -------- |
| 70%      | 注意 | 管理画面に表示               | ✅       |
| 85%      | 警告 | 管理者へ通知                 | 表示のみ |
| 95%      | 緊急 | 新規アップロードの停止を検討 | 表示のみ |

削除待ち（論理削除から30日以内）のファイルも R2 の容量を使っています。
`deleted_bytes` を別に数えているのはそのためです。
管理画面では「片付ければこれだけ空く」として出しています。

### このままだといつ埋まるか

記録が2件以上あれば、増え方から日数を見積もります
（`features/ops/lib/capacity.ts` の `daysUntilFull`）。

ごく単純な一次の見積もりです。**当てるためではなく、気付くために出しています。**
増えていない、または減っているときは何も出しません。

### 数えるのは誰か

集計と掃除は、他人の行や削除済みの行を触るため、
`security definer` の関数（0016）を通します。理由は2つあります。

1. `upload_sessions` の `with check` が「作成者が自分」になっている。
   管理者でも他人のセッションは書き換えられない
2. `files` の SELECT ポリシーが `deleted_at is null` なので、
   論理削除済みの行を更新しようとすると弾かれる
   （PostgreSQL は更新後の行にも SELECT ポリシーを適用する）

どちらもポリシーの書き方の問題ではないので、関数の中で権限を確かめる形にしています。

### いまは手で押す

日次で自動的に走らせたいところですが、動かす仕組み（cron）を1つ増やすと、
そのぶん運用が重くなります（3章の11）。
まずは `/admin/storage` から押す形にしました。記録は1日1件なので、何度押しても増えません。

## 7. 費用の目安

2026年8月時点の公開価格による概算です。実際の請求は各社の最新価格を確認してください。

| 項目                   | 目安                          |
| ---------------------- | ----------------------------- |
| Cloudflare R2 保存     | 約 $0.015 / GB / 月           |
| Cloudflare R2 下り転送 | **無料**                      |
| Supabase               | 無料枠あり。有料は月 $25 から |
| YouTube 限定公開       | 無料                          |

R2 を選んでいる大きな理由が **下り転送が無料**という点です。
動画は「1回上げて何度も見る」ものなので、転送量課金があると
使えば使うほど費用が増えます。

25GB なら保存費用は月 $0.4 程度です。
