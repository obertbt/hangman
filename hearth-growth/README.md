# Hearth Growth

親しい人だけで、勉強・運動・読書・仕事などの日々の努力を共有するクローズドなライフログです。
不特定多数への公開やフォロワー獲得は目的にしません。他人との比較より、自分の継続を大切にします。

> このディレクトリは、リポジトリのルートにある Discord Bot（`hearth-life`）とは別のプロダクトです。
> 依存も設定も混ざらないよう `hearth-growth/` 配下で完結しています。

- コメントは開いたときに読み込む（最初から全件は取らない）

### Phase 5 でできること

- タイムライン（閲覧できる投稿を新しい順に20件ずつ、「さらに読み込む」で追加）
- ホーム画面に「今、頑張っている人」を表示（カテゴリーと経過時間だけ）
- ホーム画面の今日の活動時間・件数・連続記録日数
- 活動中メンバーは1分ごとに取り直す（画面を見ているときだけ）

ランキングは使いません。並び順は投稿日時だけで決まります。

### Phase 4 でできること

- タイマー終了後、そのまま記録として残す（振り返りは任意）
- 手動での記録（カテゴリーと時間だけでよい。よく使う長さは1タップ）
- 記録の編集と削除（削除は論理削除）
- 公開範囲の指定: 自分だけ / グループ / 選んだ人
- 「選んだ人」に指定できるのは、同じグループにいる相手だけ

タイマー由来の記録では、活動時間をクライアントから受け取りません。
セッションに保存された値を DB 側で使うため、後から書き換えられません。

### Phase 3 でできること

- カテゴリーの追加・編集・並び替え・「使わない」設定（設定画面）
- タイマーの開始（カテゴリーを選ぶだけ。タイトルとメモは任意）
- 一時停止・再開・終了・記録せずに取り消す
- 画面を閉じても、再読み込みしても、正しい経過時間から再開する
- 同時に動かせるタイマーは1つだけ
- 12時間を超えて続いているタイマーには確認を出し、終了時刻を直せる（自動終了はしない）

タイマーの状態遷移と時間の計算は、すべて DB の関数が行います。
経過時間の基準を Postgres の `now()` 1か所に固定するためです。
画面はサーバーが返した時刻から表示を始め、端末の時計とのずれを補正します。

## セットアップ

### 1. 依存関係

```bash
cd hearth-growth
npm install
```

### 2. 環境変数

```bash
cp .env.example .env.local
```

`.env.local` に Supabase プロジェクトの URL と anon key を設定します。
未設定のまま起動すると、どの変数が足りないかを表示して起動時に停止します。

> service role key は使いません。RLS を迂回する経路を作らないためです。

### 3. データベース

[Supabase CLI](https://supabase.com/docs/guides/cli) を使う場合:

```bash
supabase start          # ローカルの Postgres を起動
npm run db:reset        # migrations と seed.sql を流し直す
```

ホストされた Supabase プロジェクトを使う場合は、
`supabase/migrations/` の SQL を番号順に SQL Editor で実行してください。

| ファイル                   | 内容                                               |
| -------------------------- | -------------------------------------------------- |
| `0001_initial_schema.sql`  | テーブル・制約・インデックス・トリガー             |
| `0002_rls_policies.sql`    | RLS の有効化と全ポリシー                           |
| `0003_rpc.sql`             | 招待の受理など、RLS では表現しない手続き           |
| `0004_storage_avatars.sql` | プロフィール画像用バケットとそのポリシー           |
| `0005_timer_rpc.sql`       | タイマーの状態遷移（開始・停止・再開・終了・取消） |
| `0006_post_rpc.sql`        | 活動記録の作成・編集・論理削除と、公開範囲の検証   |

RLS が意図どおり効いているかは `supabase/tests/rls_test.sql` で確認できます
（[実行方法](supabase/tests/README.md)）。

`seed.sql` はローカル専用です（テストユーザー 2 名とグループを 1 つ作ります）。

> スマートフォンだけで公開して確認する手順は [docs/DEPLOY.md](docs/DEPLOY.md) にあります。
> Supabase の SQL Editor へ貼るだけで済む [`supabase/setup.sql`](supabase/setup.sql)（1ファイル版）と、
> スマートフォンでも切れずに貼れる [`supabase/setup/`](supabase/setup/)（6分割版）を用意しています。

### 4. 起動

```bash
npm run dev
```

http://localhost:3000 を開きます。

## 設計上の約束

実装を進めるときに崩さない前提です。

- **権限判定は RLS が唯一の正。** 画面側の出し分けは体験のためであり、権限ではありません。
- **service role key をクライアントへ置かない。**
- **サーバーでは `getUser()` を使う。** `getSession()` は Cookie を検証しません。
- **`user_id` をクライアントから受け取らない。** 常に `auth.uid()` を使います。
- **タイマーの秒数を画面側で保持しない。** 表示は常に `started_at` からの再計算です。
  ブラウザを閉じても再読み込みしても、同じ計算で復元できます。
- **削除は原則として論理削除。** ただし SELECT ポリシーは投稿者を無条件に許可します
  （そうしないと `deleted_at` を立てる UPDATE 自体が RLS に弾かれます）。
  **一覧を取得する側が `deleted_at is null` で絞ってください。**
- **入力値は必ず Zod で検証する。** 同じスキーマをクライアントとサーバーの両方で使います。
- **`?next=` をそのままリダイレクト先にしない。** `safeRedirectPath()` を通します。
- **認証エラーの原文を画面に出さない。** 対応表にない場合は一律の文言にします。
- **1回の活動時間は 24 時間まで。** 12 時間を超えて続いているタイマーは、
  自動終了させずに次回ログイン時へ確認を出します。

## テスト

現時点で検証しているのは、フェーズをまたいで壊れると困る部分です。

- 活動時間の表示規則（`45分` / `1時間25分`）
- 経過時間の計算（一時停止・再開・再読み込み・端末時計のずれ）
- タイムゾーン基準の「今日」「今週」と、夏時間の切り替え日
- 連続記録日数
- 環境変数の検証
- RLS の付け忘れ検出（全テーブルで有効化とポリシーの存在を確認）
- 下部ナビゲーションの現在地表示
- 認証まわりの入力スキーマ（パスワード長・表示名・確認入力の一致）
- 認証エラーの文言変換（未知のコードで内部情報を出さない）
- プロフィールと画像アップロードの検証（MIME・容量）
- オープンリダイレクトの防止

- グループと招待の入力スキーマ（期限なし・上限なしの招待を作れないこと）
- 招待エラーの文言変換
- カテゴリーとタイマーの入力スキーマ
- 活動記録の入力スキーマ（公開範囲の組み合わせ、時間の相互変換）
- 投稿日時の表示（たった今 / ◯分前 / 日付、タイムゾーンをまたぐ場合）
- リアクションの種類とコメントの入力スキーマ
- 目標の入力スキーマと達成率（超過しても100%で止めること）

### E2E テスト

```bash
npx playwright install chromium   # 初回のみ
npm run build
npm run test:e2e
```

既定では Supabase が無くても動く範囲を確認します（57項目）。

- 未ログイン時の振り分けと、ログイン後に元のページへ戻る動作
- 入力検証の案内
- スマートフォン幅で横スクロールが出ないこと、タップ領域が44px以上あること
- PWA（マニフェスト・アイコン・検索避け・オフライン用ページ）
- アクセシビリティ（axe による自動チェック）

ログインが要る流れは `e2e/authenticated/` にあります。
Supabase を用意した環境で `E2E_SUPABASE=1 npm run test:e2e` を実行すると動きます。
